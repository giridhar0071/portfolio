## Problem Statement

The site's job is to convince both a recruiter skimming for 30 seconds and an engineer/hiring manager doing real technical diligence that Giridhar — an early-career Agentic AI Engineer — is worth interviewing. Right now the three case studies (Loan Eligibility System, Secure Note, E-Wallet Microservices) are described in detail but not provable: no live demo link, no GitHub repo link. A skeptical reader has to take the claims on faith.

## What Makes This Cool

Turning "early career" from a liability the site quietly works around into the actual pitch: someone who ships real, verifiable systems fast and teaches what they learn (50+ students taught C/Python) is a different, stronger signal than years of tenure. The fix isn't more content — it's making what's already true easy to verify.

## Constraints

- Solo maintainer, portfolio site, no CMS — content lives in `src/data.js`.
- Two concurrent full-time roles (Hexaware, Fast Flyrr) mean limited time for net-new asset creation (recording demo videos, writing new case studies).
- Some proof points (GitHub repo links for the 3 case study projects, more colleague testimonials) require the user to gather them outside this session — not something Claude Code can fabricate or fetch on its own.
- Verified during this session: `PROFILE.github` in `src/data.js` is still the literal placeholder `https://github.com/` (never filled in). `PROFILE.linkedin` (real) and the résumé file (`/Sai_Giridhar_Bandla_Resume.docx`, already linked sitewide) both already exist as real, populated assets — no net-new asset creation needed for those two. This directly resolves the tension with the constraint above: a GitHub proof link is a one-line data fix, not new asset creation.
- `PROFILE.cert` ("AWS Certified Developer") has no verification URL or credential ID anywhere in the codebase today — treated as an open question below, not assumed ready.

## Premises

1. Early-career credibility comes from verifiable, concrete work, not years of experience — the existing 3 case studies + two live AI-engineering roles + 50+ students taught is already unusually strong signal for this career stage. — AGREED
2. The current biggest gap isn't content, it's proof: none of the 3 case studies link to a live demo, GitHub repo, or video, so a skeptical hiring manager has to take the claims on faith. — AGREED
3. The Hero/About narrative describes *what* is built but not *why an early-career engineer specifically* is a good bet — that story is scattered across sections instead of stated up front. — AGREED
4. The testimonials pipeline already built (invite → admin approve → public) only has value once it holds real colleague testimonials, not just teaching quotes — collecting them is part of the same "verifiability" push as premise 2, applied to social proof instead of project proof. — AGREED

## Recommended Approach

**Approach B: Verifiable Career Story**, right-sized after review to what's actually justified by the premises and buildable without new asset creation:

- Case study proof links (GitHub repo and/or live demo per project, or an explicit no-public-link fallback — spec'd below).
- An explicit early-career narrative sentence in Hero/About.
- A minimal "proof strip": GitHub (real URL, fixing the placeholder found in Constraints) + LinkedIn (already real) + Résumé (already real, already linked elsewhere). **Certs is deferred out of the strip** — including it isn't justified by the agreed premises (case-study verifiability + narrative gap) and would require a verification URL that doesn't exist yet; see Open Questions.
- A push to collect more colleague testimonials through the pipeline already built (`/admin` → mint link → send to a Hexaware/Fast Flyrr colleague).

This directly serves premise 2 (proof/verifiability) sitewide — not just on case studies — and premise 3 (narrative), without pulling in an unjustified new surface. The code parts (links, narrative sentence, proof strip) can ship in one session once the two blocking inputs below are answered; testimonial outreach is a separate, user-owned, longer-running task.
